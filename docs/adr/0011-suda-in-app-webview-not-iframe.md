# 0011-速达应用内打开网页采用独立 WebView 窗口（非 iframe）

> **状态：已实施**（决策于「速达功能优化」设计讨论，2026-09-24；术语见 `CONTEXT.md` 的「速达」一节。2026-09-24 修订：载体扩为双载体、窗口池上限定为 4。2026-09-25 实施并拍板三项待定，见文末修订节。2026-09-25 二次修订：窗口池上限 4→2→1——轻量入口后每扇常驻仅 ~17-34MB，最终保留单窗、全部页面收进 tab，`POOL_FULL` 随 `POOL_SIZE` 动态生成且在池=1 下实际不可达。）

## 问题

速达的网页条目现在一律丢给系统默认浏览器打开（`commands.rs` 的 `launch_resource` → `process::open_url`）。要新增「应用内打开」：内嵌形态选 iframe 还是 WebView？载体是独立窗口、主窗口内嵌面板，还是两者兼有？多 tab 又受什么窗口约束？

## 决策

**用 WebView（Tauri WebviewWindow / WebView2），不用 iframe；载体两个都要：独立「应用内浏览器」窗口 + 主窗口内嵌面板。** 默认点击条目即应用内打开，浏览顶栏常驻「用系统浏览器打开」出口。多 tab 只做两件事：轻量 tab 条（打开第二个页面才出现）+ 同地址复用（重复点同一 URL 激活已有 tab）；**不做同域合并**。WebView 走**预创建常驻、只切显隐**：独立窗口池**上限 4 个**，开满提示先关一个，**不做 LRU 自动杀**（避免误关正在看的页）；内嵌面板为单实例常驻、不占池名额（可逆的实现默认）。默认落点、面板布局、面板是否带 tab 待下一轮拍板。

## 依据

- iframe 被两道闸同时封死：自家 CSP 的 `frame-src` 只放行 `http://*.localhost` 与 `xhub-ext:`（`tauri.conf.json` → `app.security.csp`），目标站的 X-Frame-Options / CSP frame-ancestors 还会再拒一道——对「任意网址」这个前提 iframe 不成立。
- 双载体并行：「点开看一眼」与「多 tab 连续查」是两种使用强度，单一载体硬兼顾会两头不讨好——内嵌面板轻量、独立浏览窗承载重浏览（2026-09-24 拍板「都要」，覆盖原「只做独立窗」建议）。
- 默认应用内 + 系统浏览器兜底：银行、强防盗链、特殊协议站点必然有应用内打不开的，不留系统浏览器出口就是给自己埋坑。
- 不做同域合并：合并规则难定义（子域算不算同域？路径前缀怎么截？）且收益低；同地址复用已覆盖最高频的「反复开同一个站」场景。
- 窗口运行时动态创建/销毁是本项目踩过的坑：现场 build WebView2 窗口会与并发窗口操作交错把整窗卡死（`floating_ball.rs:605` init 注释、`:874-875`；`chat_window.rs:7`、`notify.rs:13`、`lib.rs:438` 同一口径），所以池预创建、运行期只 show/hide。
- 不做 LRU 自动杀：自动关最久未用可能误关正在看的页；4 个上限下「提示先关一个」的打扰成本很低。

## 后果

- wry 在宿主未注册 `new_window_req_handler` 时直接拒绝新窗口请求，`target="_blank"` / `window.open` 全静默失效（`extension.rs:954-955` 已踩过并注释）——页面里的「新开窗口」链接必须宿主接管进 tab 条，不能指望页面自己弹窗。
- 「打开网页」的默认语义从系统浏览器变为应用内：`launch_resource` 的 Web 分支与 `open_url_with_browser`（指定浏览器）的分工要重新划分；http/https 白名单校验沿用。
- 同地址复用的判定先按完整 URL 精确匹配起步（可逆的实现默认，要更聪明的匹配另起讨论）。
- 每个常驻 WebView2 实例都有内存成本，池上限成为显式约束；已定：上限 4、开满提示先关一个、不做 LRU 自动杀。
- 内嵌面板与壁纸透底 / 玻璃卡片的合成层级冲突是已知风险（原建议只做独立窗，拍板「都要」后保留）：实现时面板区用实底遮罩隔离（同约定 38 的浮层深玻璃实底做法），或面板显示期间暂停壁纸透底；若实现代价超预期，回来重议。
- 面板布局落点、默认打开落点（面板 vs 独立窗）、面板是否带 tab（倾向单页无 tab、轻量 tab 条只属于独立窗）待下一轮。

## 修订（2026-09-25，实施记录 + 三项待定拍板）

- **实现形态**：Rust 侧新模块 `suda_browser.rs`——启动期预创建主窗面板 child webview（`suda-panel`）+ 独立窗池 4 扇（`suda-web-0..3`，每扇 chrome/content 双子 webview，chrome 在上层），运行期只 show/hide/navigate/set_bounds/eval，零 build/destroy（约定 41 口径）。tauri 启用 `unstable` 特性（`Window::add_child` / `Webview::set_bounds` 所需）。前端新增 `SudaWebPanel.vue`（面板视图）与 `BrowserChrome.vue`（独立窗顶栏，label 路由 `suda-web-*-chrome`）。
- **三项待定已拍板**：① 默认打开落点 = **内嵌面板**，可设置（`suda_web_open_mode`：panel/window，设置 → 功能 → 速达「网页默认打开方式」），右键菜单可临时换载体；② 面板布局与扩展 view 形态一致（主区整页视图：自绘工具栏 + 内容区子 webview，矩形由前端 ResizeObserver 上报、`set_bounds` 跟随）；③ 面板**单页无 tab**（维持倾向），面板内 target=_blank 默认原地导航。
- **选路规则**：同地址复用（完整 URL 精确匹配）→ 新页面优先落「最近显示的可见窗口」新 tab（tab 条 ≥2 才出现）→ 空闲窗口 → 池满报 `POOL_FULL` 提示先关一个（无 LRU）。独立窗用系统边框、进任务栏（区别于应用内浮窗）；`suda-panel` 与 content webview 不进 capabilities（外站页面零 IPC）。
- **待实机复核**：窗口缩放时 content 边界跟随的时序观感；隐藏常驻窗首开时 chrome 页（SPA）的加载延迟；面板与壁纸透底的合成层级（本版未做实底遮罩特殊处理，若实机发现穿透/发灰再回本 ADR 重议）；新窗口请求已注册 `on_new_window` 宿主接管（Deny + 事件回宿主）。

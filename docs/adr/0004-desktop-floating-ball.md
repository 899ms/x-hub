# 0004-桌面悬浮球（环形快捷菜单导航枢纽）

> **状态：已实施**（v0.5.0：Rust 侧 `floating_ball.rs` + 前端 `FloatingBallWindow.vue`；术语见 `CONTEXT.md`「桌面悬浮球」节）。

桌面悬浮球采用「**导航枢纽 + 环形快捷菜单**」形态，而非面板式快捷启动器（macOS Dock 式）或纯状态球：单击球体在周围展开一圈圆形按钮（大圆径向排布，非六边形/九宫格），直达现有功能；球体本身保持简洁（产品 icon 的 3D 玻璃质感球）。

## 关键决策

- **常驻方式**：仅主窗口隐藏时显示（主窗口打开即收起），与托盘 + `Ctrl+Shift+Space` 心智衔接；**常驻独立透明无边框置顶窗口**（复用 countdown_window.rs 的窗口模式），非惰性创建，避免每次唤出 0.5s+ 延迟。
- **平台范围**：Windows-only，`#[cfg(target_os = "windows")]` 隔离，macOS 留待后续。
- **交互模型**：拖拽移动并记忆位置（可停在任意位置）/ **靠近屏幕边缘时才自动吸附**（不隐藏，不收起只留边）/ 单击展开环形菜单 / 双击显示主窗口 / 右键弹出与托盘一致的菜单 / 悬停球体 3D 光泽旋转（无 tooltip 提示）。吸附语义后经「实施修订（贴边自动隐藏取代贴边吸附）」改版为半隐 + 悬停整窗滑出。
- **空间自适应**：环形菜单展开时若靠边导致按钮显示不全，悬浮球自动向左/右临时挪位保证大圆完整显示，收起后回到吸附位置。
- **按钮语义**：混合型——按钮可配置为「切换现有视图」或「快捷动作（唤起全局搜索/剪贴板/AI 面板/新建速记等）」，默认 6 个，在设置中可增删调整。
- **设置入口**：设置页「常规」分区（启用开关 + 环形按钮配置 + 吸附开关），默认开启。
- **视觉**：产品 icon 置于 **3D 玻璃质感球体**上（多向径向渐变营造球面高光/暗边 + 内圈光晕），悬停时球面光泽扫光旋转 + 光晕呼吸，与现有 Bento 玻璃风格统一。球体不设状态点、不做提示。
- **关闭方式**：点击环形外空白 / 再点球体 / Esc / 窗口失焦，四种均可收起。
- **与托盘分工**：共存——托盘管退出 + 窗口显隐，悬浮球管桌面可视化入口；右键菜单复用托盘菜单定义，改一处两处生效。

## 放弃的备选

- 纯快捷启动器面板（Q1-A）：一键直达价值大但与本项目「全局快捷键 + 托盘」现有入口重复，且面板形态无径向菜单的科技感。
- 状态球（Q1-B）：状态类能力二期再补，避免一版贪多。
- 惰性创建窗口（Q7-B）：每次唤出有窗口创建延迟，与「桌面常驻入口」定位矛盾。

## 实施修订（v0.5.0）

- **开关不再销毁窗口**：初版把「停用 = `win.destroy()`、启用 = 运行时 `build()`」当惰性重建用，实测反复开关悬浮球会**整窗未响应卡死**——运行时现场创建/销毁 WebView2 窗口是主线程长任务，与悬浮球菜单收拢/几何切换等窗口操作在主线程事件循环上交错时 WebView2 controller 创建挂起（剪贴板浮层踩过同款坑，见 `clipboard.rs::init_overlay_window` 注释）。现改为**启动无条件预创建 + 隐藏常驻**，停用只 `hide()`、启用只经 `sync_with_main()` 显隐联动，绝不运行时 build/destroy（`floating_ball.rs::init/apply_enabled`）。全局铁律见 AGENTS.md 关键约定 41。

## 实施修订（DPI 失配自愈）

- **非整数缩放下球体两侧被裁**（用户反馈：设置系统缩放 110% 或调整过显示缩放后，点击悬浮球左右两侧被遮盖一点）：110% 属自定义缩放（DPI 106，scale = 1.104166…非整数），悬浮球窗口常驻隐藏——隐藏期间 DPI 变化可能错过 `WM_DPICHANGED`（或 Win10/远程会话关闭「拖动时显示窗口内容」时 tao 在 `WM_DPICHANGED` 里显式跳过尺寸缩放），tao 缓存的 `scale_factor` 与窗口物理尺寸都停在旧值，而 WebView2 光栅化用窗口实时 DPI → CSS 视口从 100 缩到 ~90.6px，球体最外圈陀螺环（视觉 ~94.8px，两侧仅 ~2.4px 余量）被窗口边缘裁掉一截；旧 `apply_geometry` 用缓存 scale 算目标尺寸（`round(100×1.0)=100`），失配永远修不回来。对策四层（`floating_ball.rs`「DPI 自愈」注释）：
  1. **几何计算一律 `GetDpiForWindow` 实时取 DPI**（`window_scale`），与 WebView2 换算同源，缓存过期也能算对；
  2. **`apply_geometry` 用窗口实际 `outer_size` 推球心 + 按实时 scale 重设目标尺寸**——任何开合/显示都顺带把失配拉回（`PRE_EXPAND_POS` 由存左上角改为存球心，恢复与窗口实际尺寸解耦）；
  3. **窗口事件挂 `ScaleFactorChanged`**：收到 DPI 变化立即按当前态重算几何；
  4. **前端 resize 失配自检兜底**：视口与期望逻辑尺寸（`ball_size`/`menu_size` 经 state 下发）差超 1.5px 时调 `floating_ball_reapply` 重算。

## 实施修订（贴边自动隐藏取代贴边吸附）

- **原「贴边吸附」从未真正生效**（用户反馈），改为**贴边半隐 + 悬停整窗滑出**：露出/隐回由 Rust「边缘监视循环」`edge_tick`（100ms 轮询 `GetCursorPos` + 窗口矩形，直接 `SetWindowPos` 搬窗口）完成，不依赖 WebView 指针事件与 CSS 平移——原生拖拽模态循环吞事件、半截屏外透明窗命中区不稳，都曾让前端 hover 方案时好时坏（`floating_ball.rs` 模块注释）。关闭开关时 `unpop_to_inside` 把停靠的球拉回完全屏内。
- **滑出量 = 窗口半边长**（`BALL_SIZE/2` = 50 逻辑 px，即整窗完全进入屏内）。早期按球半径 `BALL_R`（24px）平移，半隐时留在屏外的 26px 依旧被切——悬停只露出球体一小半，最外圈陀螺环（视觉半径 47）与周围粒子始终看不见（用户反馈「鼠标挪上去没有显示整个球体和周围的粒子」）。
- **吸附触发距离 `DOCK_TRIGGER` = 120 逻辑 px（球心距工作区边缘；球缘距屏边 ≤ 96px 才算贴边）**，铁律是它必须 **> 滑出量 50 + 位置容差 `POS_TOL`(10 物理 px)**，否则「完整屏内、刚好贴边」的自由位置与滑出位几何上无法区分，监视循环会把用户放好的球当停靠残留拽回去。120 的定界依据用户实测数据：真贴边的松手点球心距边 4~103px（103 是「靠边了但不吸附」的抱怨点，必须覆盖），而用户明确称为「不靠边的地方」的松手点最小是 146px。**教训：吸附带曾按单次抱怨一路放宽到 200，结果 146~199 的自由放置也被吸走，球从松手点滑到屏边被感知为「没靠边也自己挪一下/抖动」——吸附带必须按「真贴边带」定界，不按单次抱怨扩**；吸附动作本身（松手后球平滑滑到屏边，~80ms）是预期行为。
- **半隐位向屏内多露 `PEEK`（8 逻辑 px，`dock_hidden_pos` 统一计算）**：球心精确压屏边时视觉只露 24px 一条弧，观感像「球直接进去了」（用户反馈）；收 8px 后露出约 2/3 球体，悬停滑出仍是整窗进屏，两态差异依旧明显。`edge_tick` 与 `drag_end` 必须共用 `dock_hidden_pos`，口径分叉会互相判成「位置漂移」。
- **拖拽松手检测在监视循环做，绝不能用 `startDragging()` 的 promise 当结束信号**：实测该 promise 在拖动开始时就 resolve，前端在 then 里调 drag_end 读到的是拖动中途位置（与最终位置差几百 px，日志实证：`拖拽松手 球心=(937,527)` 而窗口实际在 (368,464)），吸附/记忆全错，冷却后「落位补齐」再把球从屏边搬回中途——「拖到边缘松手，球弹回屏幕中间」的根因。前端位移超阈值移交原生拖动时调 `floating_ball_drag_begin` 仅记录武装时刻；`edge_tick` 发现左键释放后的第一跳执行 `settle_drag`（钳制/吸附/落位/写记忆一次做完，末尾 emit `floating-ball-settled` 让前端重拉停靠边）。
- **所有窗口搬移都是异步 IPC，`settle_drag` / 补齐搬窗后武装 `LAST_DRAG_SETTLE_MS` 冷却（800ms）**：监视循环在间隙读到「窗口旧位置 + 新记忆」会误判（日志曾见松手后立刻连刷「停靠纠偏」、记忆 y 乱跳）。落位搬窗丢失不当场复读补搬——监视循环时序下已无必要，交给冷却后的「落位补齐」按记忆收敛。滑出/隐回的 `slide_to` 在监视线程内串行执行且目标位都在候选集里，天然无此竞态。
- **停靠记忆是唯一真相，窗口向记忆收敛（不反向改记忆）**：实测即使补搬，drag_end 发出的搬窗在拖动刚结束的 ~200ms 内仍可能被吞（日志：`落位复查 补搬一次` 后纠偏读到的仍是旧位置 1849）。旧纠偏「以窗口为准改记」把刚吸附的位置改漂（记忆 y 在 446→435→416→365 间乱跳）。球被拖走必经 drag_end 重写记忆，轮询期间记忆不可能过期——窗口不在停靠几何上时补搬到（光标停在球上→滑出位，否则→半隐位）；自由位记忆同理补齐到记忆位。
- **工作区矩形一律用 `nearest_work_rect` + 监视循环无条件救球**：窗口完全离屏时 `current_monitor()` 返回 None，`drag_end` 的钳制/吸附/落位整段失效、记忆写成屏外坐标 → 手速快把球甩出屏外后「点不到也拖不回」的死锁（该场景下旧日志完全静默）。`nearest_work_rect` 兜底取「中心最近」的显示器；`edge_tick` 在 AUTO_HIDE 检查之前先判球心（窗口中心）是否出工作区，出界即钳回 + 写记忆。半隐停靠的球心恰在边缘线上，不会误触发。
- **停靠身份需「记忆球心」与「窗口实际位置」双向一致**（`at_hidden` / `at_popped` 之一在 `POS_TOL` 内）：窗口实际位置两个候选位都不等 → 说明球已被拖到别处（`drag_end` 尚未落盘的 100ms 间隙，或原生拖拽收尾丢失）→ `edge_tick` 以窗口为准重算记忆球心并撒手，**绝不再按旧记忆搬窗**。旧版只信记忆球心，于是出现「一旦吸过边，拖到屏幕任意位置都会弹回边缘」；滑出/半隐两态也改由实际位置判定而非 `POPPED` 缓存，DPI 自愈与菜单展开钳制造成的几何漂移都能自纠正。
- 落位算法抽为 `dock_snap`（`drag_end` 与 `edge_tick` 共用，两轴独立、角上可双侧停靠），避免两处口径分叉。
- **发版审查补充（v0.5.3 全批审查后）**：① 武装标志从布尔改为**武装时刻 + 30s TTL**，并新增 `floating_ball_drag_cancel`（`startDragging` 启动失败时前端 catch 调用清零）——否则失败/窗口隐藏等链路残留的标志会把用户下一次无关的左键单击松开当成拖拽落位，违背「带外绝不移动」；② 记忆球心增加**进程内缓存**（`memo_ball`，写点 `unpop_to_inside`/救球/`settle_drag` 三处同步更新、仅写盘成功时更新）——`edge_tick` 100ms 一跳不能每跳读配置文件（同 `AUTO_HIDE` 缓存理由），常态驻留下每跳读盘 = 每秒 10 次永久后台 IO；③ `settle_drag` **先写盘成功再搬窗**——写盘失败（磁盘满）时窗口与记忆保持一致（拖拽整体未生效 + warn 日志），否则「记忆=唯一真相」会把球按旧记忆拉回、整次拖拽等于没发生；④ 菜单展开钳制从整屏矩形改用 `nearest_work_rect`（同 dock/救球口径），贴底边停靠时展开的菜单不再伸进任务栏遮挡 6 点方向按钮。
